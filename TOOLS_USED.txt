Recon Framework - Tools / APIs Used Per Module
================================================

1) Subdomain Enumeration (all-in-one)
   File: backend/modules/recon/subdomains_all_in_one.py
   Type: PASSIVE
   Sources merged:
     - crt.sh            https://crt.sh                              (certificate transparency logs)
     - CertSpotter        https://api.certspotter.com                 (certificate transparency logs, free tier)
     - HackerTarget        https://api.hackertarget.com/hostsearch/    (passive DNS / hostsearch, free tier ~50-100 req/day/IP)

2) Port Scan
   File: backend/modules/recon/portscan.py
   Type: ACTIVE (sends traffic to the target)
   Tool used:
     - nmap (local binary, called via the python-nmap library)

3) Directory / Endpoint Discovery
   File: backend/modules/recon/endpoints.py
   Type: ACTIVE (sends requests to the target)
   Sources merged:
     - Built-in static wordlist (hand-picked common paths: admin panels, .git, .env, config files, etc.)
     - Wayback Machine results (reuses wayback.txt from module 7 below, if already run)
   Library: requests (direct HTTP/HTTPS calls to the target)

4) DNS Records Enumeration
   File: backend/modules/recon/dns_records.py
   Type: MOSTLY PASSIVE (zone-transfer attempt is active - goes to the target's own nameservers)
   Library: dnspython
   Queries: A, AAAA, MX, NS, TXT, CNAME, SOA records + AXFR (zone transfer) attempt

5) WHOIS / RDAP Lookup
   File: backend/modules/recon/whois_lookup.py
   Type: PASSIVE
   Source:
     - RDAP bootstrap service   https://rdap.org   (redirects to the correct registry's RDAP server)

6) Tech Fingerprint + TLS Info
   File: backend/modules/recon/tech_fingerprint.py
   Type: ACTIVE (one HTTP(S) request + one TLS handshake to the target)
   Libraries: requests (HTTP headers + generator meta tag), ssl/socket (TLS certificate details)

7) Wayback Machine URL Discovery
   File: backend/modules/recon/wayback_urls.py
   Type: PASSIVE
   Source:
     - Internet Archive CDX API   http://web.archive.org/cdx/search/cdx

8) URL Pattern Filter (gf-patterns-inspired)
   File: backend/modules/recon/url_pattern_filter.py
   Type: PASSIVE, zero network calls (re-reads wayback.txt from module 7)
   Inspired by: Gf-Patterns  https://github.com/1ndianl33t/Gf-Patterns
   Categories: xss, redirect, ssrf, sqli, lfi, rce, idor, debug_logic, interesting_ext
   Note: implemented directly in Python (param-name/extension matching), not a
   call-out to the real `gf` CLI tool.

9) URL Cleaner (uro-inspired)
   File: backend/modules/recon/uro_filter.py
   Type: PASSIVE, zero network calls (re-reads wayback.txt from module 7)
   Inspired by: uro  https://github.com/s0md3v/uro
   Drops boring static-asset extensions and collapses near-duplicate URLs
   (same path pattern + same query-param names, different ID/value).
   url_pattern_filter.py (module 8) prefers this module's output
   (uro_urls.txt) if present, falling back to raw wayback.txt otherwise.

10) XSS Reflection Prober (dalfox-inspired)
   File: backend/modules/recon/xss_prober.py
   Type: ACTIVE (sends crafted requests to the target)
   Inspired by: dalfox / kxss reflection-detection technique
   Reads: url_patterns.txt (module 8) for URLs tagged "xss"
   Method: injects a marker with HTML-significant characters into each query
   param, flags it if the marker reflects back UNESCAPED (signal, not proof,
   of reflected XSS - no <script> payload is injected or executed).

11) Subdomain Enumeration (subfinder)
   File: backend/modules/recon/subfinder_enum.py
   Type: PASSIVE (subfinder only queries public data sources)
   Tool used:
     - subfinder (industry-standard Go CLI, projectdiscovery)
       https://github.com/projectdiscovery/subfinder
       install: go install -v github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest
   Command: subfinder -d <domain> -silent -o <target_path>/subfinder.txt
   Output: subfinder.txt - one subdomain per line, deduplicated + sorted
   Note: runs alongside module 1 (all-in-one). Either or both can be used.

12) URL Dedupe (urldedupe)
   File: backend/modules/recon/urldedupe_filter.py
   Type: PASSIVE, zero network calls (re-reads wayback.txt from module 7)
   Tool used:
     - urldedupe (industry-standard Go CLI, ameenmaali)
       https://github.com/ameenmaali/urldedupe
       install: go install -v github.com/ameenmaali/urldedupe@latest
   Method: pipes wayback.txt into `urldedupe -s` (stdin), captures stdout
   Output: urldedupe.txt - unique URLs only
   Note: runs alongside module 9 (uro_filter). Both stay available.

13) URL Pattern Extraction (gf)
   File: backend/modules/recon/gf_extractor.py
   Type: PASSIVE, zero network calls (re-reads urldedupe.txt from module 12,
         falling back to wayback.txt from module 7)
   Tool used:
     - gf (industry-standard Go CLI, tomnomnom) with the Gf-Patterns set
       https://github.com/tomnomnom/gf
       install: go install -v github.com/tomnomnom/gf@latest
       patterns: git clone https://github.com/1ndianl33t/Gf-Patterns ~/.gf/patterns
   Command: for pattern in xss, sqli, ssrf, lfi, rce, redirect, idor,
   debug_logic: pipe input URLs into `gf <pattern>`
   Output: gf_<pattern>.txt per category (gf_xss.txt, gf_sqli.txt, ...)
   Note: runs alongside module 8 (url_pattern_filter). Pattern names match
   module 8's categories so downstream modules can consume either output.

14) Parameter Collector
   File: backend/modules/recon/param_collector.py
   Type: PASSIVE, zero network calls (pure file merge)
   Reads: subfinder.txt (module 11) + cleaned URLs - urldedupe.txt
     (module 12) preferred, then uro_urls.txt (module 9) /
     wayback.txt (module 7) as fallbacks
   Method: combines the subdomains + URLs, keeps only lines containing '?'
     (parameterized URLs), deduplicates, and stores the single worklist
     for the active-testing phase.
   Output: all_params.txt - ready for the XSS Prober (module 10) or the
     future vuln_scan modules, so they don't re-merge per-tool outputs
     themselves.


15) Live Host Discovery (httpx)
   File: backend/modules/recon/httpx_live.py
   Type: ACTIVE (sends HTTP requests to every subdomain found)
   Tool used:
     - httpx (industry-standard Go CLI, ProjectDiscovery)
       https://github.com/projectdiscovery/httpx
       install: go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest
   Command: httpx -silent -status-code -title -tech-detect
            -mc 200,301,302,401,403,404 (hosts piped in via stdin)
   Reads: subfinder.txt (module 11) preferred, subdomains.txt (module 1)
     as fallback (source tags stripped so httpx only sees bare hostnames)
   Output: live_hosts.txt - one line per alive host, e.g.
     "https://sub.example.com [200] [Page title] [nginx]"
   IMPORTANT: on purpose it does NOT keep only 200 OK - 401/403
     (access-restricted) and 404 hosts are kept too because they are
     often the most interesting attack surfaces. Filtering happens
     later, in module 16.

16) Live Host Status-Code Splitter
   File: backend/modules/recon/httpx_filter.py
   Type: PASSIVE, zero network calls (re-reads live_hosts.txt from module 15)
   Method: splits live_hosts.txt by the status code annotated in each
     httpx line; code set mirrors module 15's -mc list
   Output: live_200.txt, live_301.txt, live_302.txt, live_401.txt,
     live_403.txt, live_404.txt (a file per code, only written when hits
     exist; stale files from previous runs are cleaned)
   Note: the 401/403 files double as a direct-access shortlist - those
     hosts exist but are access-restricted, usually worth a manual look.


17) Web Crawling (katana)
   File: backend/modules/recon/katana_crawl.py
   Type: ACTIVE (crawls the target's live web servers)
   Tool used:
     - katana (industry-standard Go CLI, ProjectDiscovery)
       https://github.com/projectdiscovery/katana
       install: go install -v github.com/projectdiscovery/katana/cmd/katana@latest
   Command: katana -list <temp-input> -silent -jc -d 3 -o
            <target_path>/katana_urls.txt
     -jc  extract + crawl endpoints embedded in JavaScript files
     -d 3 depth cap so crawling cannot recurse forever
   Reads: live_200.txt (module 16) preferred, live_hosts.txt (module 15)
     as fallback (httpx annotations ' [200] [Title]' stripped, URLs only)
   Output: katana_urls.txt - discovered URLs, form entries and
     JS-crawl endpoints, one per line, deduplicated + sorted

18) JavaScript File Extractor
   File: backend/modules/recon/js_extractor.py
   Type: PASSIVE, zero network calls (re-reads katana_urls.txt from module 17)
   Method: keeps only lines ending in .js (incl. .min.js) or carrying a
     query string after .js (.js?ver=...)
   Output: js_files.txt - the JS attack surface: files can hide API
     routes, parameter names and dead code pointing at removed panels.
     Feeds the active-testing phase alongside all_params.txt (module 14).

Core backend stack (not recon-specific):
   - Flask        (web framework / API routes)
   - requests     (HTTP client, used by most modules above)
   - python-nmap  (Python wrapper around the nmap binary)
   - dnspython    (DNS queries for module 4)

All of the above are free and require no API key. HackerTarget and
CertSpotter have free-tier rate limits (shared per public IP); if either
is temporarily exhausted, the subdomain module still returns results from
whichever sources succeeded, with a note about which one was skipped.
